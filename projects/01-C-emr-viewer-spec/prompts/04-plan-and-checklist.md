# 04. 계획과 완료 기준

배우는 것

- 완료 기준을 구현 전에 정하기
- 구현 후에 정하면 만든 것에 맞춰 기준이 정해짐

## 프롬프트 1

```text
spec.md 와 specs/tech-stack.md 를 바탕으로 같은 디렉터리에 plan.md 를 써라.
어떻게 구현할지, 어떤 파일을 만들고 고칠지, 데이터를 어떻게 읽고 변환할지.

tech-stack.md 가 쓰지 않는다고 한 것을 넣지 마라.
넣어야 한다면 먼저 근거를 설명하고 내 확인을 받아라.
```

## 프롬프트 2

```text
같은 디렉터리에 tasks.md 와 checklist.md 를 써라.

tasks.md: plan 을 번호 붙인 그룹으로 쪼갠 것. 각 그룹은 독립적으로 구현하고 확인할 수 있게.
checklist.md: 이 단계가 끝났다고 판정하는 기준.
- 자동으로 확인할 것: 실행할 명령과 기대 결과
- 사람이 직접 확인할 것: 브라우저에서 무엇을 보면 되는지
- 적용되는 원칙을 어떻게 확인할 것인지
- 이 단계에서 요구하지 않는 것
```

---

## 무엇을 보아야 하는가

- `checklist.md`의 항목이 실제로 확인 가능한지
  - 확인 불가: "데이터 파이프라인이 잘 동작한다"
  - 확인 가능: "파생 데이터를 지우고 `npm run prepare-data`를 실행하면 같은 파일이 생긴다"
- `roadmap.md`가 이 단계에 걸어 둔 원칙을 어떻게 확인하는지 적혀 있는지. Phase 1이라면 원칙 4와 6
  - 원칙 4(정확 일치): 없는 ID와 공백이 섞인 ID로 확인
  - 원칙 6(하드코딩 금지): 데이터를 바꿨을 때 화면 숫자가 따라 바뀌는지로 확인
- `plan.md`에 새 의존성이 조용히 들어가 있지 않은지

## 여기서 멈추고 확인

- [ ] `checklist.md`의 모든 항목이 명령이나 관찰로 판정 가능함
- [ ] "요구하지 않는 것"이 적혀 있음. 범위가 새는 것을 막음
- [ ] 새 의존성이 있으면 근거가 `plan.md`에 있음
- [ ] 아직 코드는 한 줄도 없음
