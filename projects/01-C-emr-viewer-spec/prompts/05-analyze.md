# 05. 정합성 검사

배우는 것

- 문서 4개가 서로 어긋나 있음
- 구현하기 전에 잡기

## 프롬프트 1

```text
specs/ 의 강사 제공 문서 4개와 이 단계의 spec.md, plan.md, tasks.md, checklist.md 를
나란히 놓고 검사해라.

- spec 에 있는데 tasks 에 없는 것
- tasks 에 있는데 spec 에 근거가 없는 것
- checklist 가 확인하지 않는 spec 항목
- plan 이 tech-stack 을 벗어난 부분
- 원칙을 어기는 부분
- roadmap 이 이 단계에 요구하지 않은 범위

찾은 것을 목록으로 보고해라. 고치기 전에 먼저 보고해라.
```

## 프롬프트 2 (보고를 읽고 무엇을 고칠지 정한 뒤)

```text
<고칠 항목>을 반영해서 해당 문서를 갱신해라.
```

---

## 무엇을 보아야 하는가

- 전형적으로 이런 것들이 나옴
  - `spec.md`에 쓴 요구사항이 `tasks.md`에 빠져 있음. 구현되지 않고 넘어감
  - `tasks.md`에 없던 작업이 들어 있음. 다음 단계 기능을 미리 만들려는 것
  - `checklist.md`가 `spec.md`의 절반만 확인함. 완료 판정이 헐거움
- "어긋난 게 없습니다"가 나오면 문서가 서로 베낀 것일 수 있음
- `spec.md`와 `tasks.md`가 같은 문장을 쓰고 있으면 검사가 의미 없음

## 여기서 멈추고 확인

- [ ] 보고를 읽고 무엇을 고칠지 내가 판단함
- [ ] 에이전트가 보고 없이 바로 고치지 않았음
- [ ] `roadmap.md`가 요구하지 않은 범위가 남아 있지 않음
