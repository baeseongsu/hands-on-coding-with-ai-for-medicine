# 03. 모호함 찾기

배우는 것

- 방금 쓴 스펙이 두 가지로 읽히는 지점 찾기
- 구현 전에 발견하는 비용과 구현 후에 발견하는 비용의 차이

## 프롬프트 1

```text
방금 쓴 spec.md 를 구현하려는 사람의 눈으로 다시 읽어라.
두 가지 이상으로 해석될 수 있는 문장을 모두 찾아라.

각각에 대해 어떻게 해석할지 추측하지 말고 나에게 물어라.
모호한 곳이 없으면 없다고 말하고, 억지로 질문을 만들지 마라.
```

## 프롬프트 2 (질문에 답한 뒤)

```text
내 답을 반영해서 spec.md 를 갱신해라.
```

---

## 무엇을 보아야 하는가

- 에이전트가 던지는 질문은 대체로 이런 종류
  - 파생 데이터를 한 파일로 둘지, 테이블별로 나눌지
  - SHA-256이 맞지 않으면 빌드를 실패시킬지, 경고만 할지
  - 최소 화면에 무엇이 보여야 완성인지
- 모든 질문이 원래 안 정했던 것. 이 단계를 건너뛰면 에이전트가 알아서 정하고, 그 결정을 구현 후에 발견
- "모호한 곳이 없습니다"가 나오면 의심할 것. 첫 스펙에 모호함이 없는 경우는 드묾
- 그럴 때는 다시 시키거나, 스펙이 너무 짧아서 정한 게 없는 것은 아닌지 볼 것

## 여기서 멈추고 확인

- [ ] 질문이 최소 하나 나옴
- [ ] 질문 중에 "그건 생각 안 했다"가 하나라도 있었음
- [ ] 답한 내용이 `spec.md`에 들어감
