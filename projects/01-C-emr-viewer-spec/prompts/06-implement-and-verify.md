# 06. 구현과 검증

배우는 것

- 에이전트의 "완료했습니다"는 완료가 아님
- 완료 판정은 사람이 직접 하는 것

## 프롬프트 1

```text
tasks.md 를 순서대로 구현해라.
이 단계의 범위만 구현하고 다음 단계 기능을 미리 만들지 마라.
그룹을 하나 끝낼 때마다 무엇을 바꿨는지 알려라.
```

## 프롬프트 2

```text
checklist.md 의 자동 확인 항목과 프로덕션 빌드를 실행해라.
각 항목의 통과 여부와 실제 출력을 함께 보고해라.
통과하지 못한 항목을 통과한 것처럼 쓰지 마라.

그다음 내가 브라우저에서 직접 확인할 절차를 순서대로 알려줘라.
```

## 직접 확인

```bash
shasum -a 256 data/mimic-iv-clinical-database-demo-2.2.zip   # 처음 값과 같아야 함
rm -rf <파생 데이터 경로> && <문서화된 재생성 명령>            # 하나의 명령으로 복구되어야 함
```

기대한 동작:

## 무엇을 보아야 하는가

- 여기가 이 단계의 핵심. 에이전트 보고를 읽고 넘어가지 말고 `checklist.md`의 "사람이 직접 확인할 것"을 하나씩 할 것
- Phase 1이라면 위 두 명령 외에 브라우저에서 `10000032`를 검색해 그 환자가 실제로 나오는지 볼 것. 빈 화면이나 오류 화면이 아니어야 함
- 보고와 실제가 다른 경우가 있음. "테스트 통과"인데 테스트가 0개일 수 있음. 출력을 같이 요구한 이유
- 파생 데이터가 커밋되지 않았는지. `git status`로 확인
- ZIP이 그대로인지. 원칙 7

## 피드백을 줄 때

- 구현 방법을 지시하지 말고 관찰한 것을 줄 것
- 원인 판단은 에이전트가 하고, 사람은 근거를 제공
- 처음부터 "이 파일 이렇게 고쳐"라고 하면 에이전트가 잘못된 원인 위에서 고침

## 여기서 멈추고 확인

- [ ] ZIP의 SHA-256이 처음과 같음
- [ ] 파생 데이터가 커밋되지 않았음
