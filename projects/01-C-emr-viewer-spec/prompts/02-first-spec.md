# 02. 첫 스펙

배우는 것

- 에이전트가 파일을 쓰기 전에 사용자에게 질문함
- 무엇을 만드는지와 어떻게 만드는지를 분리해서 쓰기

## 프롬프트 1

```text
specs/roadmap.md 에서 완료되지 않은 첫 phase를 찾아 그 이름으로 브랜치를 만들어라.

그다음 파일을 쓰기 전에 나에게 세 가지를 물어라.
- 범위: 이 단계에서 사용자가 무엇을 할 수 있게 되는가, 무엇은 하지 않는가
- 결정: 판단이 필요한 지점과 선택지
- 맥락: 내가 알려줘야 하는 제약

중요: 내 답을 받기 전에 어떤 파일도 만들지 마라.
```

## 프롬프트 2 (질문에 답한 뒤)

```text
답을 반영해서 specs/<번호>-<단계이름>/spec.md 를 써라.
범위, 결정과 그 이유, 적용되는 원칙과 지킬 방법, 완료 시 사용자가 할 수 있게 되는 일.

기술 선택은 넣지 마라. 그건 plan.md 에서 다룬다.
```

---

## 무엇을 보아야 하는가

- 지금까지는 요구를 던지면 에이전트가 알아서 정했음. 그 판단이 어디로 갔는지 아무도 모르는 것이 문제
- 질문이 실제로 판단을 요구했는지. "React를 쓸까요"는 이미 정해진 것이라 질문이 아님. "파생 데이터를 어떤 형식으로 둘까요"는 질문
- `spec.md`에 컴포넌트 이름이나 파일 경로가 없는지. 있으면 무엇을과 어떻게가 섞인 것이므로 `plan.md`로 옮길 것
- 답한 내용이 실제로 반영됐는지
- 질문 없이 파일을 만들었으면 지우고 다시 시킬 것. 질문 없이 쓴 스펙은 에이전트의 추측

## 여기서 멈추고 확인

- [ ] 브랜치가 만들어짐
- [ ] 에이전트가 파일을 쓰기 전에 질문함
- [ ] `spec.md`를 처음 보는 사람이 읽어도 무엇을 만드는지 알 수 있음
- [ ] `spec.md`에 기술 선택이 없음
