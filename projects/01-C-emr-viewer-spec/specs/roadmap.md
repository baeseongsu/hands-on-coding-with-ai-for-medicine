# Roadmap

세 단계입니다. 각 단계가 화면 하나로 끝나고, 그 화면을 보고 판정할 수 있어야 합니다.

각 phase에는 목표와 반드시 지킴이 있습니다.

- 목표는 한 줄입니다. 화면 구성, 표시할 컬럼, 상호작용 방식은 적혀 있지 않습니다. 그것은 여러분이 `spec.md`에 쓸 내용입니다.
- 반드시 지킴은 `constitution.md`의 원칙 중 이 phase에 적용되는 것입니다. 협상 대상이 아닙니다.

원칙 7(원본 불변), 8(스펙 없이 구현하지 않음), 9(완료 판정은 사람이)는 세 phase 모두에 적용되므로 개별 phase에 다시 적지 않았습니다.

phase를 마치면 체크박스를 채우고 다음으로 넘어갑니다.

수업 중에는 **Phase 1을 강사와 함께, Phase 2를 혼자** 돌립니다. Phase 3은 수업 후 자율입니다. 사이클을 완주해보는 것이 목적이고, phase 개수를 채우는 것이 목적이 아닙니다.

---

## Phase 1. 환자 기본 뷰

- [ ] 목표: Patient ID로 환자를 찾아 그 환자가 누구이고 언제 입원했는지 볼 수 있다.

반드시 지킴: 원칙 4(정확 일치), 원칙 6(수치는 원본에서 계산)

세 phase 중 가장 큽니다. ZIP에서 정적 데이터를 만드는 파이프라인이 여기 들어갑니다. 파생 데이터를 지우고 문서화된 하나의 명령으로 다시 만들 수 있어야 하고, ZIP의 SHA-256이 실습 전후로 같아야 합니다. 기대값은 `README.md`에 있습니다.

예시 ID `10000032`로 확인하세요.

---

## Phase 2. 도메인 뷰

- [ ] 목표: 그 환자의 진단, 처방, 검사 결과를 도메인별로 나누어 볼 수 있고, 코드가 사람이 읽을 수 있는 이름으로 표시된다.

반드시 지킴: 원칙 1(단위 혼합 금지), 원칙 3(없는 값 생성 금지), 원칙 5(관계는 논리적 추론)

`diagnoses_icd`를 `d_icd_diagnoses`에 join할 때 코드와 버전을 함께 써야 합니다. 코드만으로 join하면 조용히 다른 진단이 붙습니다. MIMIC이 `(icd_code, icd_version)` 복합키를 쓰는 이유입니다.

join key는 데이터를 읽어 직접 확인하세요. 컬럼 이름이 같다는 이유만으로 관계를 만들지 마세요.

검사 결과의 단위는 값과 분리되지 않게 다루세요. 원칙 1이 여기서 걸립니다.

---

## Phase 3. 시간축 뷰

- [ ] 목표: 입원, 퇴원, ICU 입실과 퇴실, 진단, 처방, 검사 결과를 하나의 시간순 흐름으로 읽을 수 있다.

반드시 지킴: 원칙 2(없는 시각 생성 금지)

원본 배열 순서가 아니라 시각으로 정렬합니다.

`diagnoses_icd`에는 진단 시각 컬럼이 없습니다. 정렬을 완성하려고 시각을 만들어내면 원칙 2 위반입니다. 이 데이터를 시간축에 어떻게 놓을지가 이 phase에서 판단할 부분입니다.

---

## 마무리

세 phase를 마친 뒤 확인합니다. 각 phase의 `checklist.md`에 이미 들어 있어야 하는 항목들입니다.

- 테스트와 프로덕션 빌드가 통과합니다.
- URL 직접 접근과 새로고침이 동작합니다.
- 정보가 색에만 의존하지 않고 키보드로 조작 가능합니다.
- 원본 ZIP의 SHA-256이 처음과 같습니다.
- 파생 데이터를 지우고 하나의 명령으로 복구됩니다.
- 데이터 출처, ODbL 라이선스, 비식별 Demo, 비임상 용도가 명시되어 있습니다.
- 처음 받은 사람이 `README.md`만 읽고 실행할 수 있습니다.

시간이 남으면: Vercel 정적 배포, 검사 결과 추세 차트(원칙 1 준수), 좁은 화면 대응 개선.
