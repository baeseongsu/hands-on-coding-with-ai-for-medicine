# Constitution

이 문서는 이 프로젝트의 **절대 규칙**입니다. 모든 phase에 적용되고, 스펙보다 우선합니다.

여러분이 쓴 `spec.md`가 이 원칙과 충돌하면 원칙이 이깁니다. 에이전트가 원칙을 어기는 코드를 제안하면 거부하고 다시 시키세요.

각 원칙에는 번호가 있습니다. `roadmap.md`와 `prompts/`의 파일들이 번호로 참조합니다.

---

## 의료 데이터 원칙

이 네 가지는 **어겨도 화면은 정상으로 보입니다.** 그래서 위험합니다.

### 원칙 1. 단위가 다른 값을 같은 수치 축에 합치지 않는다

같은 검사라도 단위가 다르면 다른 값입니다. mg/dL와 mmol/L를 하나의 차트나 하나의 정렬 기준에 섞으면, 그래프는 그럴듯하게 그려지고 결론은 의학적으로 틀립니다.

단위별로 나누거나, 단위를 값과 함께 표시하거나, 수치 비교를 하지 않습니다.

### 원칙 2. 없는 시각을 만들지 않는다

`diagnoses_icd`에는 진단 시각이 없습니다. 시간순 정렬을 완성하려고 입원 시각이나 추정 시각을 붙이지 않습니다. 그것은 임상 시간순을 조작하는 것입니다.

시각이 없는 기록은 시각이 없는 상태로 표시하고, 어떤 입원에 속하는지만 밝히고, 정렬에서 그 한계를 사용자에게 알립니다.

### 원칙 3. 환자의 이름이나 신원을 만들지 않는다

이 데이터에는 이름이 없습니다. 화면이 비어 보인다고 이름, 나이 문장, 병력 서술을 생성하지 않습니다. 없는 값은 없다고 표시합니다.

데이터에 있는 값을 근거로 환자가 누구인지 추론하지 않습니다.

### 원칙 4. 환자 식별은 정확 일치만 한다

Patient ID 검색에 부분 일치, 유사 일치, 자동 완성 추측을 넣지 않습니다. 임상 맥락에서 잘못된 매칭은 다른 환자의 기록을 보여주는 것입니다.

앞뒤 공백 제거는 허용합니다. 그 외의 관용은 허용하지 않습니다.

## 데이터 해석 원칙

### 원칙 5. 테이블 관계는 논리적 추론이며 선언된 foreign key가 아니다

MIMIC-IV Demo는 CSV입니다. 데이터베이스 foreign key 제약이 선언되어 있지 않습니다. 우리가 쓰는 관계는 애플리케이션이 가정하는 논리적 관계입니다.

관계를 화면에 표시할 때 물리적 제약처럼 보이게 하지 않습니다. 컬럼 이름이 같다는 이유만으로 관계를 만들지 않습니다.

### 원칙 6. 화면의 수치는 원본에서 계산한다

환자 수, 행 수, 기간 같은 값을 UI 코드에 하드코딩하지 않습니다. 전처리 단계에서 실제 데이터를 읽어 계산한 값을 씁니다.

하드코딩된 숫자는 페이지가 완성된 것처럼 보이게 만들지만, 데이터가 바뀌면 조용히 거짓이 됩니다.

## 작업 원칙

### 원칙 7. 원본 데이터를 수정하지 않는다

`data/mimic-iv-clinical-database-demo-2.2.zip`은 단일 진실 공급원입니다. 수정하거나 덮어쓰거나 그 자리에 압축을 풀지 않습니다. 파생 데이터는 별도 경로에 만듭니다.

### 원칙 8. 스펙 없이 구현하지 않는다

각 phase는 `spec.md`부터 시작합니다. 무엇을 왜 만드는지 쓰기 전에 코드를 쓰지 않습니다. 현재 phase의 범위만 구현하고, 다음 phase를 미리 만들지 않습니다.

### 원칙 9. 완료 판정은 사람이 한다

에이전트가 "완료했습니다"라고 말하는 것은 완료가 아닙니다. `checklist.md`의 항목을 사람이 직접 브라우저와 터미널에서 확인한 뒤에 완료입니다.

결과가 예상과 다르면 구현 방법을 지시하기 전에 관찰한 근거를 제시합니다.
