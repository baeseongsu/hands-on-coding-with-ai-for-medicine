# Tech Stack

기술 선택은 미리 정해져 있습니다. 여러분이 `plan.md`에서 결정할 것은 이 스택 안에서 어떻게 만들지입니다.

스택을 고정하는 이유는 두 가지입니다. 90분 안에 기술 비교로 시간을 쓰지 않기 위해서, 그리고 여러 사람의 결과물을 나란히 놓고 비교할 수 있게 하기 위해서입니다.

## 핵심

| 층 | 선택 | 이유 |
|---|---|---|
| 언어 | TypeScript | 식별자와 데이터 형태를 타입으로 붙잡아 둘 수 있습니다 |
| UI | React | 페이지를 한 번에 하나씩 붙여 가기 좋습니다 |
| 빌드 | Vite | 설정 없이 빠르고, 정적 산출물이 그대로 배포 가능합니다 |
| 데이터 | 전처리로 생성한 정적 파일 | 상시 실행되는 백엔드가 필요 없습니다 |
| 테스트 | Vitest | Vite와 같은 설정을 씁니다 |

## 프로젝트 루트 규칙

현재 프로젝트 디렉터리, 즉 `README.md`와 `specs/`와 `data/`가 있는 위치를 그대로 React/Vite 프로젝트 루트로 씁니다.

`package.json`, `index.html`, `src/`, `scripts/`, `public/`을 이 위치 기준으로 만듭니다. `app/`이나 `frontend/` 하위 프로젝트를 만들지 않습니다.

React나 Vite의 제약이 아니라, 참가자들 사이에서 명령과 경로를 일치시키기 위한 규칙입니다.

## 데이터 파이프라인

- 입력은 `data/mimic-iv-clinical-database-demo-2.2.zip` 하나입니다.
- 전처리가 ZIP을 읽어 애플리케이션이 쓸 정적 데이터를 만듭니다.
- 문서화된 하나의 명령으로 다시 생성할 수 있어야 합니다. 파생 데이터를 지우고 그 명령을 실행하면 같은 결과가 나와야 합니다.
- 생성된 파일과 원본은 경로로 명확히 구분합니다.
- 전처리 스크립트의 언어는 자유입니다. Node와 Python 3이 모두 준비되어 있습니다.

## 실행 환경

- API key 없이 모든 필수 기능이 동작해야 합니다.
- 상시 실행되는 백엔드 없이 동작해야 합니다.
- 데스크톱 브라우저를 우선하되, 좁은 화면에서 핵심 기능이 깨지지 않게 합니다.
- semantic HTML과 키보드로 접근 가능한 컨트롤을 씁니다.
- 정보를 색만으로 전달하지 않습니다.

## 쓰지 않는 것

- 데이터베이스 서버. 정적 파일로 충분한 규모입니다.
- 상시 백엔드. 필수 기능에 서버 로직이 필요하지 않습니다.
- 인증 라이브러리. 비목표입니다.
- 차트 라이브러리. 표가 필수이고 차트는 선택입니다. 넣더라도 원칙 1을 지켜야 합니다.
- 상태 관리 라이브러리. 이 규모에서 필요하지 않습니다. 필요하다고 판단하면 `plan.md`에 근거를 쓰세요.
- UI 컴포넌트 프레임워크. 넣어도 되지만 필수가 아닙니다. 시간을 쓸 만한지 스스로 판단하세요.

새 의존성을 추가할 때는 `plan.md`에 무엇을 왜 추가하는지 적습니다. 조용히 늘리지 않습니다.
